An archive is a snapshot of one user account or one guild, built in the background and downloaded as a file. [Create user archive](/admin-api/users/#create-user-archive) and [Create guild archive](/admin-api/guilds/#create-guild-archive) request one. The operations here read archive state and issue time-limited download URLs.

While Fluxer builds an archive, it leaves out any stored file that is missing from storage. Any other read or write failure fails that build attempt and sets `failed_at`.

Every operation needs an [ACL](/admin-api/#acl-evaluation) covering the subject type it touches.

- A user archive needs `archive:view_all` or `archive:trigger:user`.
- A guild archive needs `archive:view_all` or `archive:trigger:guild`.
- Reading both types at once needs `archive:view_all`, or `archive:trigger:user` and `archive:trigger:guild` together.

:::note[An expired archive stops being readable]
An archive becomes unavailable through these routes at `expires_at`, 365 days after it was requested. Its lifetime is never extended.
:::

## Archive object

An archive is in one of these lifecycle states. It is building while `completed_at` and `failed_at` are both null, complete once `completed_at` is set, and failed once `failed_at` is set. When Fluxer starts a new attempt at a failed archive, it clears `failed_at` and `error_message`, so the archive reads as building again while that attempt runs.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| archive_id | snowflake | The ID of the archive, used with its subject to address the record |
| subject_type | string | The [archive subject type](#archive-subject-types) the record is stored under |
| subject_id | snowflake | The user or guild the archive was taken of |
| requested_by | snowflake | The Admin account that requested the archive |
| requested_at | ISO8601 timestamp | The time the archive record was created |
| started_at | ?ISO8601 timestamp | The time construction began, or null while the task has not started |
| completed_at | ?ISO8601 timestamp | The time construction completed, or null when it has not completed |
| failed_at | ?ISO8601 timestamp | The time construction failed, or null when it has not failed |
| file_size<sup>1</sup> | ?string | The size of the stored archive object in bytes, or null before completion |
| progress_percent<sup>2</sup> | number | The construction progress from 0 to 100 |
| progress_step<sup>2</sup> | ?string | The step the construction task last reported |
| error_message | ?string | The failure text the construction task reported, or null when it has not failed |
| download_url_expires_at<sup>3</sup> | ?ISO8601 timestamp | The cache expiry stamped on the stored archive object at completion, or null before completion |
| expires_at<sup>4</sup> | ?ISO8601 timestamp | The time the archive stops being readable |

<sup>1</sup> The size is a decimal string

<sup>2</sup> A new archive starts at 0 with the step `Queued`, and completion sets 100 and `Completed`. Failure leaves `progress_percent` where it was and sets the step to `Failed`

<sup>3</sup> Written at completion using the archive's fixed `expires_at`. [Create archive download](#create-archive-download) returns a URL with its own expiry

<sup>4</sup> The value is 365 days after `requested_at`

### Example

```json
{
  "archive_id": "1501314428688998182",
  "subject_type": "user",
  "subject_id": "1478812292088791040",
  "requested_by": "1478812292088791041",
  "requested_at": "2026-08-14T11:02:03.000Z",
  "completed_at": "2026-08-14T11:06:41.000Z",
  "file_size": "48211904",
  "progress_percent": 100,
  "progress_step": "Completed",
  "expires_at": "2027-08-14T11:02:03.000Z"
}
```

## Archive subject types

| Value | Description |
| --- | --- |
| user | The archive captures one user account |
| guild | The archive captures one guild |

## Archive download object

This object uses camelCase field names, unlike every other Admin response body.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| downloadUrl<sup>1</sup> | string | The time-limited URL the archive file is fetched from |
| expiresAt<sup>2</sup> | ISO8601 timestamp | The time this URL stops working |

<sup>1</sup> A presigned object storage link, or a [signed download](#download-signed-file) link on the API while presigned harvest downloads are disabled. Neither carries an Admin credential, so possession of it grants access until it expires

<sup>2</sup> The value is seven days after the grant was issued, regardless of the archive's own `expires_at`

### Example

```json
{
  "downloadUrl": "https://storage.example.com/harvests/1501314428688998182.zip?signature=abc123",
  "expiresAt": "2026-09-07T11:06:41.000Z"
}
```

## List archives

<RouteHeader method="GET" path="/v1/admin/archives" auditReason />

Returns [archive](#archive-object) objects matching the supplied filters, newest first. Requires an ACL covering the requested `subject_type`.

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| subject_type?<sup>1</sup> | string | `user`, `guild`, or `all` (default `all`) |
| subject_id?<sup>2</sup> | snowflake | The exact subject whose archives are returned |
| requested_by?<sup>3</sup> | snowflake | The Admin account that requested the returned archives |
| limit?<sup>4</sup> | integer | The maximum number of archives to return (1-200, default 50) |
| include_expired?<sup>5</sup> | boolean | Whether to include archives past their `expires_at` (default false) |

<sup>1</sup> `all` returns the newest `limit` archives across both subject types, so a busy subject type can crowd out the other

<sup>2</sup> `subject_type` also has to name `user` or `guild`

<sup>3</sup> Ignored when `subject_id` is supplied. When `requested_by` applies, Fluxer ignores `subject_type` and returns that account's archives of both subject types

<sup>4</sup> The listing is not paginated and returns no cursor. Only a narrower filter reaches older records

<sup>5</sup> The value counts as true only for `true`, `True`, or `1`. Excluding expired archives can leave fewer than `limit` results

:::note[The default filter narrows to the account's ACLs]
`all` is the default, and Fluxer resolves it to the subject types the account's ACLs cover. An account holding only `archive:trigger:user` reads user archives, one holding only `archive:trigger:guild` reads guild archives, and one holding `archive:view_all` reads both. An account holding none of the three is refused with 403 `MISSING_ACL`.
:::

### Response body

| Field | Type | Description |
| --- | --- | --- |
| archives | array[[archive](#archive-object) object] | The archives matching the filters, newest first |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | The archives were returned |
| 400 | [error response](/admin-api/#error-response) | `subject_id` is supplied while `subject_type` is `all`. `INVALID_FORM_BODY` has `INVALID_FORMAT` on `subject_type` |
| 403 | [error response](/admin-api/#error-response) | `MISSING_ACL` without an ACL covering the requested subject type |

### Side effects

The operation records one [Admin audit entry](/admin-api/#admin-audit-entry-object) with action `list_archives`, target type `archive`, target ID `0`, and metadata keys `subject_type`, `limit`, `include_expired`, and `result_count`. `subject_type` is the value after Fluxer narrows `all` to the account's ACLs. The entry also has `subject_user_id` or `subject_guild_id` when `subject_id` is supplied, and `requested_by_user_id` when `requested_by` is supplied.

### Rate limit

200 requests per minute for each authenticated user, on the `admin:lookup` bucket.

## Get archive

<RouteHeader method="GET" path="/v1/admin/archives/{subject_type}/{subject_id}/{archive_id}" auditReason />

Returns one [archive](#archive-object) object. Requires an ACL covering the subject type.

### Path parameters

| Field | Type | Description |
| --- | --- | --- |
| subject_type | string | The [archive subject type](#archive-subject-types), either `user` or `guild` |
| subject_id | snowflake | The user or guild the archive was taken of |
| archive_id | snowflake | The ID of the archive |

### Response body

| Field | Type | Description |
| --- | --- | --- |
| archive<sup>1</sup> | ?[archive](#archive-object) object | The archive, or null when the subject and identifier resolve to nothing |

<sup>1</sup> A missing archive answers 200 with a null archive, which is also the answer when the identifier belongs to a different subject and when the archive has passed `expires_at`

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | response body | A lookup was done, whether or not it resolved |
| 403 | [error response](/admin-api/#error-response) | `MISSING_ACL` without an ACL covering the subject type |

### Side effects

The read issues no download grant.

The operation records one [Admin audit entry](/admin-api/#admin-audit-entry-object) with action `get_archive`, target type equal to `subject_type`, target ID equal to `subject_id`, and metadata keys `archive_id` and `found`. `found` is `false` when the response has a null archive.

### Rate limit

200 requests per minute for each authenticated user, on the `admin:lookup` bucket.

## Create archive download

<RouteHeader method="GET" path="/v1/admin/archives/{subject_type}/{subject_id}/{archive_id}/download" auditReason />

Issues a temporary download URL for a completed archive. Returns an [archive download](#archive-download-object) object on success. Requires an ACL covering the subject type.

:::caution[The grant is an unauthenticated bearer URL]
The URL has its own signature and works for seven days for anyone who holds it. It is bound to no Admin account, and no operation revokes it. Each repeat of the operation issues a further independent grant.
:::

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [archive download](#archive-download-object) object | The grant was issued |
| 400<sup>1</sup> | [error response](/admin-api/#error-response) | The archive is not downloadable, returned as `HARVEST_NOT_READY`, `HARVEST_FAILED`, or `HARVEST_EXPIRED` |
| 403 | [error response](/admin-api/#error-response) | `MISSING_ACL` without an ACL covering the subject type |
| 404<sup>2</sup> | [error response](/admin-api/#error-response) | The subject and identifier resolve to nothing, returned as `UNKNOWN_HARVEST` |

<sup>1</sup> `HARVEST_FAILED` while `failed_at` is set, `HARVEST_NOT_READY` while the archive has no completion time or no stored object, and `HARVEST_EXPIRED` once `expires_at` has passed, tested in that order

<sup>2</sup> The archive record stops being readable at `expires_at`, so an archive past its expiry answers `UNKNOWN_HARVEST`, not `HARVEST_EXPIRED`

### Side effects

The operation creates a download URL valid for seven days and changes no field of the archive, including `download_url_expires_at`. While presigned harvest downloads are disabled, which is the self-hosted default, the URL points at [Download signed file](#download-signed-file) on the public API endpoint instead of object storage.

The operation records one [Admin audit entry](/admin-api/#admin-audit-entry-object) with action `get_archive_download_url`, target type equal to `subject_type`, target ID equal to `subject_id`, and metadata key `archive_id`. The entry has no URL. A request that returns 400 or 404 records no entry.

### Rate limit

200 requests per minute for each authenticated user, on the `admin:lookup` bucket.

## Download signed file

<RouteHeader method="GET" path="/v1/signed-downloads/{filename}" unauthenticated />

Streams an archive or a file kept with a report, from a link the Admin API issued in place of a presigned object storage link.

[Create archive download](#create-archive-download), and the attachment and profile image URLs of a [report](/admin-api/reports/), use this route while presigned harvest downloads are disabled. The `token` query parameter names the stored file and its expiry, and is signed by the instance. Use the complete issued URL and keep it secret.

:::note[Every rejection looks identical]
A missing, malformed, forged, or expired token and an object that no longer exists all return 404 with the plain text body `Not Found`. So does every request while the instance issues presigned URLs.
:::

### Path parameters

| Field | Type | Description |
| --- | --- | --- |
| filename | string | File name the download is saved as (1-512 characters) |

### Query parameters

| Field | Type | Description |
| --- | --- | --- |
| token | string | Signed download token issued with the link (1-2,048 characters) |

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| Range? | string | Standard byte range, answered with 206 and a `Content-Range` header |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | file bytes | The complete file was streamed |
| 206 | file bytes | The requested byte range was streamed |
| 404 | `Not Found` | The token is missing, invalid, or expired, the file is gone, or the instance issues presigned URLs instead |
| 416 | `Range Not Satisfiable` | The requested range lies outside the file |

### Response headers

The 200 has the stored `Content-Type`, `Content-Disposition: attachment` with the file name from the path, `Content-Length`, `Accept-Ranges: bytes`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, and a sandboxing `Content-Security-Policy`. The 206 adds `Content-Range`.

### Side effects

The file is read and streamed. The token is not consumed, so it stays usable until its own expiry, which is seven days for an archive and five minutes for a report file.

### Rate limit

60 requests per minute for each client IP address, or for the authenticated account when the request has a resolvable credential, on the `user:harvest:download_file` bucket.
