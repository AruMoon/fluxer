title: Use your own proxy
description: Put nginx, Caddy or another reverse proxy in front of your Fluxer instance.
---

By default, Fluxer uses ports 80 and 443 and gets its own certificate from Let's Encrypt. If another web server on the machine already uses those ports, Fluxer can serve plain HTTP on a local port for your proxy to forward to.

## Turn it on

```sh
rexctl proxy on
```

Fluxer then listens on `127.0.0.1:8080`. To use another address or port, pass it with `--bind`:

```sh
rexctl proxy on --bind 127.0.0.1:8081
```

If your proxy runs on another machine, bind an address that machine can reach and only let the proxy connect to that port. You can also pass `--behind-proxy` to `rexctl install` to start this way, and `rexctl proxy off` goes back to Fluxer's own certificate.

Your proxy can use `/_health` as its health check.

## What your proxy needs to do

- Serve your domain over HTTPS and accept TLS 1.2 as well as TLS 1.3. The mobile apps play videos with a library that only supports TLS 1.2.
- Forward WebSocket connections.
- Set `X-Forwarded-For` to the address the request came from, and drop any value the visitor sent.
- Accept request bodies of at least 512 MB for uploads.
- Keep idle connections open for an hour.
- Pass the `Sec-Fetch-Site` header through unchanged.
- Don't add a `Content-Security-Policy` header. Fluxer sends its own.

Forward every path and query string to Fluxer unchanged.

## nginx

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    listen [::]:80;
    server_name chat.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name chat.example.com;

    ssl_certificate     /etc/letsencrypt/live/chat.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chat.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 512m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        proxy_set_header Host            $host;
        proxy_set_header Upgrade         $http_upgrade;
        proxy_set_header Connection      $connection_upgrade;
        proxy_set_header X-Forwarded-For $remote_addr;

        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_request_buffering off;
        proxy_buffering off;
    }
}
```

Use `$remote_addr` for `X-Forwarded-For`. `$proxy_add_x_forwarded_for` keeps the value the visitor sent, and anyone could then pretend to come from another address.

## Caddy

```caddy
chat.example.com {
	reverse_proxy 127.0.0.1:8080
}
```

Caddy's defaults already do everything in the list above, and Caddy gets the certificate for your domain itself.

## Cloudflare

If Cloudflare proxies your domain, change these settings in the Cloudflare dashboard:

- Turn Rocket Loader off. With it on, the web app shows a blank page.
- Don't let a Cache Rule store HTML pages, or people get an old version of the web app after you upgrade.
- Turn Bot Fight Mode off and don't add challenges for `/api/`, `/gateway` or `/livekit/`. The desktop and mobile apps can't solve a challenge.
- Set the SSL/TLS encryption mode to "Full (strict)" when Fluxer gets its own certificate.

## Voice and video

Voice and video calls don't go through your proxy. They connect to TCP port 7881 and UDP port 7882 on the machine directly, and both ports need to stay open. A tunnel such as Cloudflare Tunnel can't forward them, and an instance that you only serve through a tunnel has no voice or video calls.
