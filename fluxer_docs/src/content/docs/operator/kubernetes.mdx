The Helm chart in `deploy/helm/fluxer` runs the same Fluxer services as rexctl does on one machine, and it generates its own secrets. rexctl doesn't manage a Kubernetes install. You install and upgrade with Helm, and run the instance from the admin panel.

## What you need

- Kubernetes 1.29 or newer, and Helm 3 or Helm 4.
- About 2 CPUs and 8 GB of memory free for the release.
- A default StorageClass with `ReadWriteOnce` volumes.
- An ingress controller and cert-manager. With `edge.expose: loadBalancer` you need neither, and Fluxer gets its own certificate.
- An `A` record for your domain that points to the ingress controller or the load balancer.
- TCP port 7881 and UDP port 7882 open on the node that runs LiveKit, for voice and video calls.

The install stops with a message when the cluster is missing something it needs.

## Install

Get the chart and write a values file with your domain:

```bash
git clone --depth 1 https://github.com/fluxerapp/fluxer.git
printf 'domain: chat.example.com\n' > fluxer-values.yaml
```

Install it into its own namespace:

```bash
helm install fluxer ./fluxer/deploy/helm/fluxer \
  --namespace fluxer --create-namespace \
  -f fluxer-values.yaml --wait --timeout 15m
```

Keep `fluxer-values.yaml` for upgrades. When the install is done, `helm test fluxer -n fluxer` checks that your instance answers on your domain.

Open your domain in a browser to create your admin account. The setup page asks for the setup token, which is in the chart's Secret:

```bash
kubectl -n fluxer get secret fluxer-env -o jsonpath='{.data.FLUXER_SETUP_TOKEN}' | base64 -d
```

## Values

The chart's `values.yaml` explains every value. These are the ones most installs change.

| Value | What it sets |
| --- | --- |
| `domain` | The address people use for your instance |
| `email` | The contact address for Let's Encrypt and web push |
| `edge.expose` | `ingress`, `gateway`, `loadBalancer` or `none` for a proxy of your own |
| `livekit.expose` | `hostNetwork`, `loadBalancer` or `nodePort` for the voice ports |
| `env` | Fluxer settings as `NAME: value` |
| `secrets.extra` | Settings that hold a password or a key |

The ingress controller in front of Fluxer must see the real address of each visitor. Set `externalTrafficPolicy: Local` on its Service, or turn on the PROXY protocol between the load balancer and the controller. Otherwise every visitor shares one address and hits the same sign-in limits.

Under Argo CD, set `secrets.generate: false` and give every secret in `secrets.values`, or name a Secret you manage in `secrets.existingSecret`.

## Upgrade

Pull the chart and upgrade with the same values file. A new `image.revision` makes every pod pull the latest images:

```bash
git -C fluxer pull
helm upgrade fluxer ./fluxer/deploy/helm/fluxer -n fluxer -f fluxer-values.yaml \
  --set-string image.revision=$(date +%s) --wait --timeout 15m
```

`helm rollback` goes back to the previous values and images, but it doesn't undo changes to the database.

## Back up

Back up the Secret and the database:

```bash
kubectl -n fluxer get secret fluxer-env -o yaml > fluxer-env.yaml
kubectl -n fluxer exec postgres-0 -- sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > fluxer.dump
```

Keep `fluxer-env.yaml` as safe as the database. A restored database needs the same Secret to work.

Uploads are on the volume `data-seaweedfs-0`. Back it up with a snapshot from your storage provider.

## Restore

Put the Secret back before you install, and the new release uses the same secrets:

```bash
kubectl create namespace fluxer
kubectl apply -f fluxer-env.yaml
helm install fluxer ./fluxer/deploy/helm/fluxer -n fluxer -f fluxer-values.yaml --wait --timeout 15m
```

Stop everything except Postgres, restore the database and restore the uploads volume from its snapshot:

```bash
kubectl -n fluxer scale deployment,statefulset --replicas=0 \
  -l 'app.kubernetes.io/part-of=fluxer,app.kubernetes.io/name notin (postgres)'
kubectl -n fluxer exec -i postgres-0 -- sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < fluxer.dump
```

Then run the same `helm upgrade` without `image.revision` to start everything again.

## Uninstall

```bash
helm uninstall fluxer -n fluxer
```

The Secret and the volumes stay, and a new install with the same release name and namespace uses them again. To delete everything, delete them too:

```bash
kubectl -n fluxer delete secret fluxer-env
kubectl -n fluxer delete pvc -l app.kubernetes.io/instance=fluxer
kubectl delete namespace fluxer
```
