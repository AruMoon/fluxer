These routes take payment for premium. Checkout finishes on the payment provider's own pages, so the checkout routes create the provider session and return its URL for the browser to open. [Receive Stripe webhook](#receive-stripe-webhook) takes the signed events the provider sends back. The [Premium resource](/http-api/premium/) owns entitlement state, mirrored billing data and subscription self-service.

A self-hosted deployment serves the checkout routes only while billing is active, and serves [receive Stripe webhook](#receive-stripe-webhook) while Stripe is serviceable, as [deployment availability](/http-api/deployment-availability/) describes. All of them are user-only except [receive Stripe webhook](#receive-stripe-webhook).

:::note[Every response is a Fluxer object]
The responses are Fluxer redirect and acknowledgement objects.
:::

## Redirect URL object

One absolute URL that completes a billing operation in a browser. [Create subscription checkout](#create-subscription-checkout) and [create gift checkout](#create-gift-checkout) both answer with it. The object has no session identifier, so a client sends the browser to the returned value.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| url<sup>1</sup> | string | Absolute URL that completes the operation in a browser |

<sup>1</sup> Usually an externally hosted payment provider session URL. [Create subscription checkout](#create-subscription-checkout) can answer with the Fluxer premium callback URL instead

### Example

```json
{
  "url": "https://checkout.example.com/c/pay/cs_test_9f8e7d6c5b4a"
}
```

## Refund eligibility object

The `billing.refund_eligibility` member of [premium state](/http-api/premium/#get-premium-state). A self-hosted deployment offers no self-service refunds, so `eligible` and `cancels_subscription` are false, `reason` is `feature_unavailable`, and every other field is null.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| eligible | boolean | Always false |
| reason | ?string | Always `feature_unavailable` |
| invoice_id | ?string | Always null |
| invoice_amount_paid_cents | ?integer | Always null |
| currency | ?string | Always null |
| paid_at | ?ISO8601 timestamp | Always null |
| refund_window_expires_at | ?ISO8601 timestamp | Always null |
| cooldown_expires_at | ?ISO8601 timestamp | Always null |
| cancels_subscription | boolean | Always false |
| provider | ?string | Always null |

## Webhook received object

The acknowledgement [receive Stripe webhook](#receive-stripe-webhook) returns once it authenticates the event and queues it for asynchronous processing.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| received | boolean | Always true after the event is authenticated and accepted for processing |

### Example

```json
{
  "received": true
}
```

## Create subscription checkout

<RouteHeader method="POST" path="/v1/stripe/checkout/subscription" />

Creates a recurring premium checkout session and returns a [redirect URL](#redirect-url-object) object.

### Limitations

- An unknown price returns 400 `STRIPE_INVALID_PRODUCT`.
- A gift price, a price outside the resolved country catalogue, and an omitted country code for a price that requires one all return 400 `STRIPE_INVALID_PRODUCT_CONFIGURATION`.
- An unclaimed account returns 400 `UNCLAIMED_ACCOUNT_CANNOT_MAKE_PURCHASES`.
- An unverified email address returns 403 `PURCHASE_EMAIL_VERIFICATION_REQUIRED`.
- The purchase-disabled premium flag returns 403 `PREMIUM_PURCHASE_BLOCKED` with the reason `purchase_disabled`.
- An open payment dispute the account made returns 403 `PREMIUM_PURCHASE_BLOCKED` with the reason `payment_dispute_open`, for a subscription and a gift alike.
- A lifetime premium account cannot buy a recurring subscription and returns 403 `PREMIUM_PURCHASE_BLOCKED` with the reason `lifetime`.
- An account whose payment provider customer already holds a subscription in the `active`, `trialing`, `past_due`, `unpaid`, `incomplete` or `paused` state returns the same code with the reason `existing_subscription`, unless Fluxer converts the purchase into a scheduled billing cycle change, as described below.

`reason` is a top-level member of the error response, and an `existing_subscription` refusal also has the blocking status in the top-level `subscription_status` member.

Fluxer evaluates the lifetime refusal before the unclaimed account, unverified email and purchase flag refusals, so a lifetime premium account submitting a recurring price always receives the reason `lifetime` whatever its account state.

An account already holding an `active` or `trialing` subscription can submit a registered recurring non-gift price for the other billing cycle. Fluxer then schedules a billing cycle change to the submitted cycle at the end of the current period. That is exactly what [change subscription billing cycle](/http-api/premium/#change-subscription-billing-cycle) with `effective_at` set to `period_end` does. The response is 200 with `url` set to the Fluxer premium callback URL.

The conversion requires a stored billing cycle on the account that differs from the submitted price's cycle. Any other blocking subscription status, no stored billing cycle, and a matching cycle all still produce 403 `PREMIUM_PURCHASE_BLOCKED`. When scheduling the change fails, the caller receives that failure.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| price_id | string | Registered recurring price ID (1-256 characters) |
| country_code?<sup>1</sup> | string | Two-letter country used to select the regional price catalogue (2 characters) |
| client_geoip_country_code?<sup>2</sup> | string | Two-letter country the client previously observed for itself (2 characters) |
| eu_withdrawal_waiver_accepted?<sup>3</sup> | boolean | Whether the digital content withdrawal waiver was explicitly accepted |
| payment_method?<sup>4</sup> | string | Either `card`, `pix` or `upi` (default `card`) |
| is_business? | boolean | Whether to require a billing address for tax invoicing (default false) |

<sup>1</sup> Read only when Fluxer cannot geolocate the request, because the request-time geolocation country wins. The resolved country is required whenever the price is not in USD or EUR, and the price is validated against the catalogue for that country, so a client cannot buy outside the catalogue of the country it is browsing from

<sup>2</sup> Read to resolve the effective country for the withdrawal waiver, and recorded with the payment

<sup>3</sup> Considered only when the effective country is inside the European Union or European Economic Area. The effective country is the request-time geolocation country, then the client-observed country, then the pricing country

<sup>4</sup> `pix` requires a BRL recurring price and `upi` requires an INR recurring price. Both are rejected for a gift price or a non-recurring price with 400 `STRIPE_INVALID_PRODUCT_CONFIGURATION`.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [redirect URL](#redirect-url-object) object | The checkout session was created, or a blocked purchase was converted into a scheduled billing cycle change |
| 400<sup>5</sup> | [error response](/http-api/#error-response) | The price, the account, or the payment provider blocks the checkout |
| 403 | [error response](/http-api/#error-response) | The email address is unverified, or the purchase is blocked |
| 404 | [error response](/http-api/#error-response) | The authenticated account record no longer exists |

<sup>5</sup> The price is unknown or not valid for the resolved catalogue, the account is unclaimed, the payment provider is not configured, or the payment provider rejected the request and returns `STRIPE_ERROR`

### Side effects

Checkout collects the required consent, tax information and any promotion code on the provider's pages.

A converted purchase schedules a billing cycle change instead of opening checkout. It clears pending cancellation and sends [User Update](/gateway/events/#user-update) to every account session.

Premium entitlement otherwise changes only after the matching signed event reaches [receive Stripe webhook](#receive-stripe-webhook).

### Rate limit

3 requests per minute for each authenticated user, on the `stripe:checkout:subscription` bucket.

## Create gift checkout

<RouteHeader method="POST" path="/v1/stripe/checkout/gift" />

Creates a one-off premium gift checkout session and returns a [redirect URL](#redirect-url-object) object.

### Limitations

- The claimed account, verified email, purchase flag and open payment dispute requirements of [create subscription checkout](#create-subscription-checkout) apply unchanged, with the same codes.
- The submitted price is a registered gift price for the resolved country catalogue, so a recurring price returns 400 `STRIPE_INVALID_PRODUCT_CONFIGURATION`.

Neither the lifetime block nor the existing subscription block applies here, so a lifetime premium account can buy gifts.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| price_id | string | Registered gift price ID (1-256 characters) |
| country_code?<sup>1</sup> | string | Two-letter country used to select the regional gift price catalogue (2 characters) |
| client_geoip_country_code? | string | Two-letter country the client previously observed for itself (2 characters) |
| eu_withdrawal_waiver_accepted? | boolean | Whether the digital content withdrawal waiver was explicitly accepted |
| is_business? | boolean | Whether to require a billing address for tax invoicing (default false) |
| payment_method? | string | Either `card`, `pix` or `upi`, which this operation ignores |

<sup>1</sup> Read only when Fluxer cannot geolocate the request, because the request-time geolocation country wins. The resolved country is required whenever the gift price is not in USD or EUR

A submitted `pix` or `upi` is validated against the enum and then discarded. The session restricts no payment method type, so the provider offers whatever the deployment's provider account accepts for the resolved currency.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [redirect URL](#redirect-url-object) object | The checkout session was created |
| 400<sup>2</sup> | [error response](/http-api/#error-response) | The price, the account, or the payment provider blocks the checkout |
| 403 | [error response](/http-api/#error-response) | The email address is unverified, or the purchase is blocked |
| 404 | [error response](/http-api/#error-response) | The authenticated account record no longer exists |

<sup>2</sup> The price is unknown or is not a gift price for the resolved catalogue, the account is unclaimed, the payment provider is not configured, or the payment provider rejected the request and returns `STRIPE_ERROR`

### Side effects

The returned URL opens a one-off checkout. The [gift](/http-api/gifts/#gift-object) appears in [List current user gifts](/http-api/users/gifts/#list-current-user-gifts) only after payment is confirmed.

### Rate limit

3 requests per minute for each authenticated user, on the `stripe:checkout:gift` bucket.

## Receive Stripe webhook

<RouteHeader method="POST" path="/v1/stripe/webhook" unauthenticated />

Accepts a signed payment provider event for asynchronous processing and returns a [webhook received](#webhook-received-object) object. The signature header is the credential.

### Limitations

- A missing signature header returns 400 `STRIPE_WEBHOOK_SIGNATURE_MISSING`.
- A deployment with no payment provider client or webhook secret configured then returns 400 `STRIPE_WEBHOOK_NOT_AVAILABLE`.
- A signature header that does not verify returns 401 `STRIPE_WEBHOOK_SIGNATURE_INVALID`.

:::caution[The signature covers the exact bytes]
A proxy that re-encodes, reorders or pretty-prints the payload invalidates the signature.
:::

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| Stripe-Signature | string | Payment provider signature computed over the exact raw request body |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [webhook received](#webhook-received-object) object | The event was authenticated and queued |
| 400 | [error response](/http-api/#error-response) | The signature header is missing, or webhook processing is not configured for this deployment |
| 401 | [error response](/http-api/#error-response) | The signature did not verify against the raw body |
| 500 | [error response](/http-api/#error-response) | The event could not be queued |

### Side effects

The response comes before processing, and a redelivered event is applied once.

Accepted events update payment, subscription, gift and dispute results. Resulting account changes reach connected sessions as [User Update](/gateway/events/#user-update).

### Rate limit

300 requests per minute for each client IP address, or for the authenticated user when a credential happens to be supplied, on the `stripe:webhook` bucket. The bucket is exempt from the global bucket.
